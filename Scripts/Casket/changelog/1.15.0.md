# 1.15.0

- added: `settings security sandbox network outbound enable|disable|state`
  — opt-in real outbound connectivity for `exec` sessions, on top of the
  existing `namespaces net` isolation. Sets up a veth pair + host-side
  NAT (MASQUERADE, scoped to the sandbox's own veth interface only) for
  the duration of each `exec` session.
- added: `settings security sandbox network inbound
  add|remove|list|enable|disable|state` — opt-in real port forwarding
  from a host port into whatever's listening inside the sandbox, via a
  host-side DNAT rule. Independent of `outbound` (either, both, or
  neither can be active).
- Both are torn down automatically on `exec` exit via a privileged
  helper process forked before any namespace/capability drop (so
  teardown still works even after the CLI process itself enters a
  restricted user namespace), with a crash-recovery sweep on next use
  and a `flock`-based lock preventing two concurrent sessions from
  stomping each other's networking. Everything is hand-rolled raw
  `AF_NETLINK` (`NETLINK_ROUTE` + `NETLINK_NETFILTER`) — no `ip`/`nft`
  shell-out, no netlink crate, matching this project's existing
  hand-rolled-primitives style (`sandbox/seccomp.rs`'s raw BPF builder).
- Deliberately kept separate from `namespaces net` itself: `net` alone
  stays fully contained (loopback only, zero host mutation); `outbound`/
  `inbound` are the two settings that touch the host's own routing/NAT
  tables.
