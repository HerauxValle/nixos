# 1.9.1

- added: `settings security fileIntegrity enable|disable [--delete-backup]
  | state` — migrates the vault to (or off of) a dm-integrity-protected
  LUKS2 container, so a corrupted or tampered byte anywhere in the
  vault's actual files gets detected instead of silently decrypting to
  garbage. Requires the vault open; copies every file to a fresh
  container, verifies it byte-for-byte (SHA-256 per file, via
  `migrate::copy_tree`/`verify_tree` from 1.9.0), then swaps it in.
  Old container preserved at `.<vault>.backup.img` unless
  `--delete-backup` is passed. An interrupted migration is safe to
  re-run — the partial staging container is resumed, original vault
  untouched until the final swap. A crash in the narrow window between
  the swap's two renames is auto-completed the next time the vault is
  resolved (`Vault::find`). Both the real vault and the staging
  container are unmounted (checked, not silently) before their mappers
  close, so the swap never happens while either is still mounted.
