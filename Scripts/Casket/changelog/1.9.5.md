# 1.9.5

- fixed: `info` (no auth needed by default) disclosed a 2FA vault's
  exact keyfile path/filename to anyone with mere read access to the
  vault directory — no passphrase required. Found via a real black-box
  pentest attempt against a purpose-built weak-passphrase 2FA vault:
  the passphrase itself held (a 15-minute rockyou.txt dictionary attack
  against the real LUKS container didn't crack it), but `info` handed
  over the second factor's location for free, which is exactly the
  piece 2FA is supposed to require actually proving something to learn.
  `info` now shows only that a keyfile is set and whether it's raw or
  embedded; the exact path requires `--pass` to verify first, same
  opt-in pattern the tamper-evidence check already uses.
