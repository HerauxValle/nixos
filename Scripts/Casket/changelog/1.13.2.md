# 1.13.2

- fixed: `settings security sandbox namespaces enable net` isolated
  `exec` into a genuinely empty network namespace — no loopback, no
  address, nothing usable — instead of the working-but-contained
  namespace it was supposed to provide. `sandbox::namespaces::
  bring_up_loopback()` now brings `lo` up with `127.0.0.1`/`::1` inside
  the new netns via a raw `ioctl(SIOCGIFFLAGS/SIOCSIFFLAGS)` call, same
  primitive `ip link set lo up` uses. No route out is still the
  intentional default (see `network outbound`, next entry) — this only
  fixes loopback being completely dead.
- changed: enabling `net` in `namespaces` now prints a one-time warning
  explaining the loopback-only/no-route-out posture at the point of use,
  instead of leaving that undocumented until someone hit it.
