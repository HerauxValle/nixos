# 1.12.5

- fixed: `settings 2fa enable|disable` rebuilt vault metadata from a
  blank default instead of the vault's actual current settings,
  silently resetting `fileIntegrity`, `backupAuto`,
  `ransomwareProtection`, `zeroize`, `bruteforceLockout`, and
  `sandbox*` back to off on every 2FA toggle
- fixed: `headerOffset`/`headerEncryption` never worked on a vault with
  `fileIntegrity` on — rebuilding the LUKS2 header didn't account for
  dm-integrity, so the operation always failed its own verify-before-
  commit check rather than corrupting anything
- breaking: `headerOffset`/`headerEncryption` and `fileIntegrity` are
  now permanently mutually exclusive, enforced with a clear error in
  both directions — confirmed live that rebuilding a LUKS2 header while
  forcing the container's existing volume key (how `headerOffset`/
  `headerEncryption` relocate/hide the header) silently corrupts a
  dm-integrity-protected container's payload; there's no safe way to
  combine the two with cryptsetup's current primitives
- changed: header room's per-slot size grew 384 KiB -> 768 KiB (slot
  count 85 -> 42) to leave headroom for a bigger LUKS2 keyslots area in
  the future; an existing room on the old layout migrates to the new
  one transparently and safely the next time it's touched, verified
  end-to-end via a real cryptsetup round-trip before the old slot is
  ever scrubbed
