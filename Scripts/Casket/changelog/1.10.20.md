# 1.10.20

- added: `cas <vault> settings security sandbox disable --removeRootfs`
  -- wipes every rootfs environment as part of disabling sandbox,
  instead of requiring `rootfs remove all` as a separate step first.
  Reuses `rootfs remove all`'s exact behavior (typed per-environment
  confirmation, refuses while any `cas exec` session is live, refuses
  if a `default` environment is still set -- removal deliberately
  doesn't auto-clear it, same "no implicit side effect" rule
  `rootfs.rs`'s own doc comment already states) rather than
  duplicating that logic. Runs *before* the sandbox flag itself is
  cleared, so a refusal (e.g. a default still set) leaves sandbox
  exactly as it was rather than disabled-with-leftover-environments.
  Requires the vault open (rootfs environments live inside the mounted
  vault) -- refuses clearly rather than silently skipping if it isn't.

Verified live against a throwaway vault: two fake rootfs environments
created via `--tarball`, `--removeRootfs` correctly refused while one
was still the `default` (sandbox stayed enabled), then succeeded with
both typed confirmations after clearing it -- both environments gone,
sandbox disabled.
