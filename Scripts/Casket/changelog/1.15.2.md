# 1.15.2

- fixed: `network inbound add 0` (or `0:8080`/`8080:0`) was silently
  accepted, creating a nonsensical port-0 DNAT rule. Port parsing now
  rejects `0` the same way it already rejected out-of-range values.
- added: `network inbound add` now checks `/proc/net/{tcp,tcp6,udp,udp6}`
  for something already listening on the target host port and prints a
  non-blocking warning if so — DNAT happens in `PREROUTING`, before the
  host's own routing/local-delivery decision, so a real service already
  on that port would have had its traffic silently stolen the moment
  forwarding was enabled, with no bind conflict or error anywhere to
  signal it.
