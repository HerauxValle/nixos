# 1.16.3

- Fixed: `cas help <path>` with a typo'd or nonexistent subcommand past a
  valid prefix (e.g. `cas help auth keyfile bogus-verb`) used to silently
  show that valid prefix's own child list, with no indication the typed
  path wasn't real. Now falls through to the same "no help topic" /
  general help behavior as any other unrecognized path.
- Fixed: the startup-time check for two commands accidentally sharing
  the same internal id only ran once something happened to touch the
  registry (`help`, `debug`, or most subcommands) — a session that only
  ever ran a plain vault verb (`create`/`open`/`exec`/...) never
  triggered it. The check now always runs at startup, regardless of
  which command is invoked.
- Fixed: `cas help settings security sandbox` showed a blank description
  for the `sandbox` entry itself (only its children had text).
