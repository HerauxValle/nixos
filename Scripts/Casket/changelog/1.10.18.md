# 1.10.18

- changed: seccomp enforcement no longer depends on `libseccomp-sys` /
  `libseccomp` — that was a hard link-time C library requirement with
  no vendored fallback, meaning `cargo build` failed outright on any
  machine (Nix or not) without `libseccomp-dev` installed. Every other
  `cas` dependency is a runtime-PATH tool check, never a link-time C
  library, so this was a real portability regression against the rest
  of the codebase.
- added: `src/sandbox/syscall_table.rs` + `data/syscalls-x86_64.toml` /
  `data/syscalls-aarch64.toml` — complete (385 / 361 entries)
  syscall-name-to-number tables, mechanically extracted from real Linux
  kernel headers (`linux-headers` 7.0: `asm/unistd_64.h` for x86_64,
  `asm-generic/unistd.h` with `__NR3264_*` alias resolution for
  aarch64). Every syscall the kernel defines for each architecture is
  included, not just the ones the shipped presets reference, so
  `custom` presets can name any of them.
- changed: `src/sandbox/seccomp.rs` rewritten from a `libseccomp-sys`
  wrapper to a hand-rolled classic-BPF filter builder — raw
  `prctl(PR_SET_SECCOMP, SECCOMP_MODE_FILTER, ...)` against a program
  built from `syscall_table`'s per-architecture lookup, checking
  `AUDIT_ARCH_*` first so a filter built for one architecture's numbers
  can never be misapplied against another's. Same "own the OS-level
  mechanics directly" precedent already used for `pivot_root`/
  namespaces — no C library dependency at build or run time anywhere in
  `cas` now.
- removed: `libseccomp-sys` from `Cargo.toml`; `libseccomp` +
  `pkg-config` from `flake.nix`'s `buildInputs`/`nativeBuildInputs`.
- fixed: `sandbox::seccomp`'s unit tests called `apply()` directly
  without first setting `PR_SET_NO_NEW_PRIVS`, which the kernel
  requires before installing any seccomp filter for an unprivileged
  caller — production code always satisfies this via `harden::apply()`
  running earlier in `sandbox::run`'s real sequence, but the tests
  bypassed that entirely and intermittently failed with `EPERM`
  (`Permission denied`) as a result. Tests now set it themselves before
  calling `apply()`, matching the real call sequence.

Verified via `cargo test` (all 18 unit tests, including all three
`sandbox::seccomp` tests, pass deterministically both in parallel and
under `--test-threads=1`) and a clean `cargo build --release` with the
`libseccomp-sys` dependency fully gone.
