# 1.10.13

- added: `rootfs update <name> [<version>] | update <name> --tarball
  <path>` — replaces `base/` only, `upper/` (anything installed/edited)
  always preserved. Refuses if the update mode doesn't match how the
  environment was originally created (`.casket-source`'s `kind`).
- fixed: `checksum_url` always stripped the tarball URL down to its
  directory before appending `checksum_suffix` — correct for Ubuntu's
  directory-relative `/SHA256SUMS` manifest, but wrong for Alpine/
  Debian's per-file `.sha256` companion (which needs the *full* tarball
  URL + suffix). Found live when `add --preset alpine <version>` (the
  pinned path) 404'd on checksum fetch. Now a leading `/` on
  `checksum_suffix` picks the directory-relative behavior explicitly;
  anything else appends to the full URL.

Verified live: pinned alpine add (checksum now resolves correctly),
placed a marker file in `upper/`, ran `update` to a newer pinned
version, confirmed `base/` changed and the `upper/` marker survived,
confirmed the tarball-mode-on-preset-environment refusal.
