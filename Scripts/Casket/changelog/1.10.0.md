# 1.10.0

- added: real weak-passphrase warnings on `create` and `auth passwd`,
  using `zxcvbn` (Dropbox's algorithm, Rust port) — proper entropy/
  crack-time estimation plus its own large embedded dictionaries
  (common passwords, English words, names, keyboard patterns, l33t
  substitutions), not a hand-rolled wordlist or a naive length/
  character-class check. Non-blocking: a weak passphrase gets a
  `[!]` warning with the specific reason and an estimated offline
  crack time, never a refusal.
- fixed: `auth passwd` refused an empty new passphrase outright
  ("passphrase cannot be empty"), unlike `create`, which generates a
  strong random one if left empty. Rotating *to* a strong passphrase
  is now exactly as easy as creating one was — leave it empty
  (interactively, or `--new-pass ""`) to generate one, same as `create`.
- added: the derived LUKS secret is now `mlock()`ed for as long as it's
  held (in addition to the zeroize-on-drop already shipped), so it
  can't get written to swap unencrypted while actively in use — zeroize
  alone only covered *after* use. Same `settings security zeroize`
  toggle governs both; not a new setting.
