# 1.12.3

- fixed (high, confirmed live): volume keys and decrypted headers
  staged during `headerOffset`/`headerEncryption` operations landed in
  `TempOutPath` files with no explicit mode (world-readable under this
  system's umask), on real disk (not tmpfs), deleted via a plain unlink
  with no zeroization -- recoverable by any other local user, or from
  disk after the fact. `TempOutPath` gained `write_secure()` (mode 0600
  from creation, now used at every header-staging call site) and a
  `shred()` that overwrites content before unlinking, called from
  `Drop` on both `TempOutPath` and the pre-existing `TempKeyfile`; a new
  `UmaskGuard` scopes the process umask to 0077 around the cryptsetup
  calls that create these files themselves (`--master-key-file`,
  `luksFormat --header`), where there's no `OpenOptions` hook available.
- fixed (dead code, low): a leftover `|| true` in `ground_truth`'s
  front-framed-encrypted structural length check made the intended
  cheap-rejection-before-expensive-crypto guard unconditionally pass.

Both found by a pentest pass reviewing the actual diff of the
`headerOffset`/`headerEncryption` implementation for key-exposure and
leftover debug code.
