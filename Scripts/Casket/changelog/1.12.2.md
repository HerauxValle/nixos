# 1.12.2

- fixed: the 1.12.1 fix to `check_tamper` had a gap in the opposite
  direction -- the tamper check couldn't fire at all when `header_
  offset`/`header_encryption` were themselves the *tampered* fields,
  since `verify_current_secret` used those same fields to decide which
  single header location to test. A hand-edit to exactly the fields the
  tamper check exists to protect made the location lookup fail
  structurally before the HMAC was ever compared, so `open` hard-failed
  instead of detecting and self-healing the tamper. Added `probe_
  location` (`header/relocate.rs`), a location-independent search that
  tries every candidate (native front, front-encrypted, room slot
  plain, room slot encrypted) and only trusts one that a real detached-
  header open actually verifies -- `verify_current_secret` falls back
  to it when the meta-directed lookup fails, so a correct secret is
  provable regardless of which fields got tampered with. `ground_truth`
  now shares the same search via `probe_location`.

Found and fixed while re-verifying 1.12.1's tamper-reset behavior by
hand-editing the trailer directly and reopening with the correct
passphrase.
