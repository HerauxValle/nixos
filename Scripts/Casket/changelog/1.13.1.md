# 1.13.1

- fixed: `settings security sandbox seccomp set strict` segfaulted a
  statically-linked (musl) binary under `exec` instead of cleanly denying
  a blocked syscall. Root cause: `arch_prctl` was missing from the
  `strict` allowlist — musl's static-binary startup calls it to set up
  TLS before `main` ever runs; denied with EPERM, TLS never gets
  established, and the very next TLS-relative access (errno, etc.)
  dereferences a null pointer. The kernel's own deny action was already
  correct (`EPERM`, confirmed via passing tests); the crash happened
  entirely inside the sandboxed process before it could observe the
  denial. Added `arch_prctl` to `strict` in
  `src/registry/data/seccomp-presets.toml`.
