# 1.10.14

- added: `src/sandbox/overlay.rs` — mounts base/upper as an OverlayFS
  view from inside the sandbox's own already-unshared mount namespace,
  torn down automatically with the rest of the namespace on exit.
- added: `cas exec --rootfs <name>` and the full resolution rule: zero
  environments falls back to the vault's own content, exactly one is
  used automatically, multiple use the `default` symlink target if set
  (refuses, listing names, if not) — `--rootfs` always overrides.

Verified live against a throwaway vault: all four resolution cases
(zero/one/multiple-no-default-refuses/multiple-with-default), plus an
explicit `--rootfs` correctly overriding a set default. Overlay mount
syntax independently verified (unprivileged, standalone): a write
through the merged view correctly lands in `upper/`, lower content
stays visible underneath. Full end-to-end `exec --rootfs` sessions
remain blocked by this dev environment's own privileged-mount
restriction (documented since 1.10.7) — needs real-hardware
verification.
