# 1.12.4

- fixed: `settings 2fa enable|disable`, `auth passwd`, and `auth
  keyfile reset` only special-cased `headerOffset` when deciding
  whether to rotate the LUKS secret via a detached-header path --
  `headerEncryption` enabled *alone* left the container's front bytes
  as unresolvable ciphertext to a plain `luks::slot_cycle`, failing all
  three with "current passphrase did not match any LUKS slot." `auth
  keyfile reset` additionally had no relocation-awareness at all
  (unconditional plain `slot_cycle`). All three now route through the
  detached path whenever either toggle is active, matching `open.rs`'s
  own `is_native_front` check.

Found by a follow-up functional pass specifically covering
`headerEncryption`-alone state combinations and 2FA/keyfile rotation
under both toggles, areas the original implementation and first
verification pass hadn't reached live.
