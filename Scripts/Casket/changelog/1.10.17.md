# 1.10.17

- added: real seccomp enforcement — `src/sandbox/seccomp.rs`, a thin
  wrapper around `libseccomp-sys` (new dependency, plus `libseccomp` +
  `pkg-config` added to the Nix package's `buildInputs`/
  `nativeBuildInputs`). Syscall names resolve to numbers via libseccomp
  itself, per the host's actual architecture — never a hardcoded
  numeric table.
- added: `cas exec` now actually applies the configured seccomp preset
  (per-rootfs, resolved the same way `--rootfs` itself resolves),
  inside the PID1 child only, inherited by the real foreground command.
  `custom` is verified against its stored hash before use — a mismatch
  or missing file falls back to `strict` rather than running unfiltered
  or on stale rules (same "fail toward more protective" rule
  `tamper::reset_to_safe` already uses for this field). An unknown
  preset name in metadata gets the same fallback.

Verified two ways: genuine unprivileged unit tests (`sandbox::seccomp::
tests`) proving the actual kernel enforcement works — a denylist blocks
exactly the named syscall, an allowlist blocks everything *not* named,
both confirmed via real syscall failures with `EPERM` in a forked
child. And live against a throwaway vault: `resolve_seccomp` integrates
cleanly into `exec`'s flow with no new failures beyond the
already-documented pivot_root privilege limitation in this dev
environment.
